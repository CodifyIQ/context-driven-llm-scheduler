# Flutter Multi-Flavor Build Configuration

## Concept

Flutter **flavors** let a single codebase produce distinct application variants per
environment without `if/else` scattered across source files. Each flavor gets its
own:

- Native app identity (bundle ID / application ID, display name)
- Compile-time configuration values injected via `--dart-define`
- Firebase project (or any other backend service)
- Optional UI indicators (e.g., a debug banner in non-production builds)

The canonical three-tier model is `dev -> staging -> prod`, where `dev` targets a
local or shared development backend, `staging` mirrors production for pre-release
validation, and `prod` is the live environment.

## Flavor Enum and Accessor (`lib/flavors.dart`)

Define a `Flavor` enum and a static `F` class that holds the runtime value.
Using `late final` makes the field write-once and eliminates null-safety noise
throughout the app.

```dart
enum Flavor { dev, staging, prod }

class F {
  static late final Flavor appFlavor;

  static String get name => appFlavor.name;

  static String get title {
    switch (appFlavor) {
      case Flavor.dev:     return 'My App (Dev)';
      case Flavor.staging: return 'My App (Staging)';
      case Flavor.prod:    return 'My App';
    }
  }
}
```

## Flavor Resolution at Startup (`lib/main.dart`)

`flutter build web` does **not** support the `--flavor` flag, so the app must
accept flavor input through two channels and prefer the explicit Dart define:

```dart
/// Reads the active flavor from the environment.
/// - Web builds: pass --dart-define=FLAVOR=<flavor>
/// - iOS/Android builds: pass --flavor=<flavor> (sets FLUTTER_APP_FLAVOR automatically)
String? _getFlavorName() {
  const explicit = String.fromEnvironment('FLAVOR');
  if (explicit.isNotEmpty) return explicit;
  return appFlavor; // built-in variable set by --flavor
}

void main() async {
  final flavorName = _getFlavorName();
  if (flavorName == null || flavorName.isEmpty) {
    throw FlutterError(
      'Application flavor not specified. '
      'Use --flavor (iOS/Android) or --dart-define=FLAVOR= (web).',
    );
  }

  F.appFlavor = Flavor.values.firstWhere(
    (e) => e.name == flavorName,
  );

  WidgetsFlutterBinding.ensureInitialized();
  await _initializeFirebase();
  runApp(const ProviderScope(child: MyApp()));
}
```

> **Why two channels?** The `--flavor` flag injects `FLUTTER_APP_FLAVOR` for
> native iOS/Android tooling but is unsupported on web. `--dart-define=FLAVOR=`
> works universally and takes precedence when both are present.

## Environment-Specific UI Indicators

Display a visible banner in non-production flavors so testers always know which
environment they are running:

```dart
class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    final isProd = F.appFlavor == Flavor.prod;
    final label  = switch (F.appFlavor) {
      Flavor.staging => 'STG',
      _              => F.appFlavor.name.toUpperCase(),
    };

    return MaterialApp.router(
      routerConfig: router,
      title: F.title,
      builder: (context, child) {
        if (isProd) return child ?? const SizedBox.shrink();
        return Banner(
          message: label,
          location: BannerLocation.topStart,
          color: const Color(0xFFB00020),
          child: child ?? const SizedBox.shrink(),
        );
      },
    );
  }
}
```

## Compile-Time Configuration Values

Inject environment-specific values at build time with `--dart-define` or
`--dart-define-from-file`. Read them in Dart with `String.fromEnvironment`:

```dart
// lib/shared/util/api_client.dart
class ApiClient {
  static const String _baseUrl = String.fromEnvironment(
    'HTTP_SERVICE_URL',
    defaultValue: '',
  );

  /// On Android emulators, replace localhost with 10.0.2.2 so the app
  /// can reach a backend running on the host machine.
  static String get baseUrl {
    String url = _baseUrl;
    if (!kIsWeb && Platform.isAndroid && url.contains('localhost')) {
      url = url.replaceAll('localhost', '10.0.2.2');
    }
    return url;
  }
}
```

Store local development values in a `.env` file that is **not committed**:

```dotenv
# dev.env  (add to .gitignore)
HTTP_SERVICE_URL=http://localhost:8000
```

> **Rule:** Never hardcode environment-specific URLs or keys directly in source
> files. Use `String.fromEnvironment` so values are baked in at build time and
> never shipped as readable strings in the final binary.

## Firebase Initialization per Flavor

Generate a separate `firebase_options_<flavor>.dart` for each Firebase project
using `flutterfire configure`, then select the correct set at startup:

```dart
Future<void> _initializeFirebase() async {
  final options = switch (F.appFlavor) {
    Flavor.dev     => dev_firebase.DefaultFirebaseOptions.currentPlatform,
    Flavor.staging => staging_firebase.DefaultFirebaseOptions.currentPlatform,
    Flavor.prod    => prod_firebase.DefaultFirebaseOptions.currentPlatform,
  };
  await Firebase.initializeApp(options: options);
}
```

Using a `switch` expression ensures the compiler surfaces an error if a new
`Flavor` value is added without a corresponding Firebase options file.

## Android Native Configuration (`flutter_flavorizr`)

Use the `flutter_flavorizr` package to generate Android product flavors. The
result is written to `android/app/flavorizr.gradle.kts` and applied from
`android/app/build.gradle.kts`.

```kotlin
// android/app/flavorizr.gradle.kts
android.apply {
    flavorDimensions("flavor-type")
    productFlavors {
        create("dev") {
            dimension = "flavor-type"
            applicationId = "com.example.myapp.dev"
            resValue(type = "string", name = "app_name", value = "My App Dev")
        }
        create("staging") {
            dimension = "flavor-type"
            applicationId = "com.example.myapp.staging"
            resValue(type = "string", name = "app_name", value = "My App Staging")
        }
        create("prod") {
            dimension = "flavor-type"
            applicationId = "com.example.myapp"
            resValue(type = "string", name = "app_name", value = "My App")
        }
    }
}
```

Each flavor gets a distinct `applicationId` so all three can be installed
simultaneously on the same device.

## Running Locally

### iOS / Android

```bash
flutter run \
  --flavor=dev \
  --dart-define-from-file=dev.env
```

### Web

```bash
flutter run -d chrome \
  --dart-define=FLAVOR=dev \
  --dart-define=HTTP_SERVICE_URL=http://localhost:8000
```

### VS Code `launch.json`

```json
{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "my_app (dev)",
      "request": "launch",
      "type": "dart",
      "args": ["--flavor=dev", "--dart-define-from-file=dev.env"]
    }
  ]
}
```

## Building Release Packages

Set flavor and backend URL before running any build command:

```bash
FLUTTER_FLAVOR=staging           # or prod
SERVICE_URL=https://api.example.com
```

### Web

```bash
flutter build web \
  --wasm \
  --release \
  --dart-define=FLAVOR=$FLUTTER_FLAVOR \
  --dart-define=HTTP_SERVICE_URL="$SERVICE_URL" \
  --build-name="1.0.0" \
  --build-number="1"
```

### Android (App Bundle)

```bash
flutter build appbundle \
  --flavor=$FLUTTER_FLAVOR \
  --release \
  --build-name="1.0.0" \
  --build-number="1" \
  --dart-define=HTTP_SERVICE_URL="$SERVICE_URL"
```

Output path: `build/app/outputs/bundle/${FLUTTER_FLAVOR}Release/app-${FLUTTER_FLAVOR}-release.aab`

Android release builds require a signing keystore. Configure it via
`android/key.properties` (not committed to version control):

```properties
storePassword=<password>
keyPassword=<password>
keyAlias=<alias>
storeFile=<absolute-path-to-keystore>
```

### iOS (IPA)

```bash
flutter build ipa \
  --flavor=$FLUTTER_FLAVOR \
  --release \
  --build-name="1.0.0" \
  --build-number="1" \
  --dart-define=HTTP_SERVICE_URL="$SERVICE_URL"
```

Output path: `build/ios/ipa/<app_name>.ipa`

## Adding Flavor-Conditional Behavior

Always use exhaustive `switch` expressions on `F.appFlavor` so the compiler
enforces handling of every flavor:

```dart
// Good - exhaustive, compile-time checked
final String endpoint = switch (F.appFlavor) {
  Flavor.dev     => 'http://localhost:8000',
  Flavor.staging => stagingServiceUrl,
  Flavor.prod    => prodServiceUrl,
};

// Avoid - not exhaustive, easy to miss a case
if (F.appFlavor == Flavor.prod) { ... } else { ... }
```

When adding a new `Flavor` value to the enum, the analyzer will immediately
highlight every `switch` expression that needs updating.

## Environment Variable Reference

| Variable             | How to pass                                  | Read in Dart via                   | Required by     |
|----------------------|----------------------------------------------|------------------------------------|-----------------|
| `FLAVOR`             | `--dart-define=FLAVOR=<value>`               | `String.fromEnvironment('FLAVOR')` | Web builds      |
| `FLUTTER_APP_FLAVOR` | Auto-set by `--flavor` flag                  | Built-in `appFlavor` variable      | iOS / Android   |
| `HTTP_SERVICE_URL`   | `--dart-define` or `--dart-define-from-file` | `String.fromEnvironment(...)`      | All platforms   |

> Additional compile-time values (feature flags, analytics IDs, etc.) follow the
> same pattern: pass via `--dart-define`, read via `String.fromEnvironment`.

## Code Generation and Asset Regeneration

Run these commands after modifying the relevant configuration files:

| Change made | Command to run |
|-------------|----------------|
| Modified `flutter_launcher_icons-<flavor>.yaml` | `dart run flutter_launcher_icons` |
